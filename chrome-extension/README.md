# Notification Manager Chrome extension

This is a local, unpacked Chrome extension for the same primary Google Calendar used by the Android app. When the Chrome profile starts, it opens a 520 × 720 dedicated popup **window**. If Chrome remains running after all normal browser windows close, opening the first normal browser window opens or focuses the manager again. The toolbar button also reopens it.

The window caches the last loaded events and dismissal records for offline reading. Dismissals save locally first and retry Drive sync when the window refreshes or the browser reconnects. Move and dismiss actions leave the newest click in Undo immediately while prior saves run in the background. Actions whose Undo period has ended are saved in an account-specific local outbox before the network write. Network failures stay visible and retry when the manager opens, refreshes, or reconnects; permanent errors remain for review through Retry unsaved actions in the menu. The manager must be open for retries to run. Retries keep the original destination and recognize moves already applied; an event changed elsewhere is flagged for review instead of overwritten. The subheader waits for the first refresh to finish and flags pending dismissals, a sync failure, or more-than-one-hour-old Calendar or dismissal data. It does not treat the browser's network hint alone as a sync failure. The menu shows one row, either “Synced just now” or “Sync issues”; click it for separate refresh times, local-only dismissals, and merged state from another device. A separate **Recent dismissals** menu row shows the ten most recent dismissed event titles. Pending changes are cleared after Drive confirms them; synced dismissal keys remain cached for offline filtering. The prior Recent actions log has been removed from storage. Review-window presets cover daily cleanup, week-ahead, meeting-heavy, monthly cleanup, and Monday-through-today.

The window loads all pages of events in the selected lookback period (7 days by default) and through the selected lookahead day (today by default, in the computer's local time zone), then scrolls within a fixed-size list. Events are ordered oldest date first, with all-day events first within each date. A Later divider in the selected skin's muted accent color precedes the first future event. The dot appears beside events whose rounded age reads at least “2 days ago.” Future events today show their local clock time (for example, “At 6:15 pm”); later days show a weekday and ordinal date (for example, “Sat Oct 3rd”). It shows title, rounded age, and location; titles open the Calendar event view while the pencil opens Google's event editor when its event link includes an `eid`. Both open a tab in a regular, non-Incognito Chrome window. Repeated title clicks within eight seconds open only one tab. `1D` is always visible: click it to move one day, or hover or focus it for more actions and the full title. The ribbon overlays the space to the left of 1D, with 1D vertically centered beside both rows of actions. Hovering does not change the event row height or title wrapping. Its compact buttons are slightly larger than the default 1D tile. The flyout always uses five columns and two rows, including in wide tabs and windows. Its top row is 1H/4H/8H/Calendar/Dismiss and its bottom row is 2D/3D/4D/pencil/7D; all-day events get 0D instead of hour options. Calendar opens the native date picker immediately, with a clock icon beside the date input. The icon opens an optional time picker initially set to the event’s start time. Selecting a date stages the same configurable Undo action without another confirmation; if the clock is unused, the event keeps its original time of day. All-day events have no clock icon. Relative move tiles still move from the current computer time; all moves preserve event duration.

The arrow beside the header refresh button moves the live manager into a regular Chrome tab, creating a normal browser window if none is open. Click the same arrow in the tab to move it back into a centered dedicated extension window. The arrow tooltip describes the next action. The toolbar button focuses the manager wherever it is open.

Save-status messages and errors use the selected skin’s accent color, with spacing between the clock and each status message.

The header shows the computer's local date, time to the minute, and current time-zone abbreviation and name. The connected account appears in the settings menu below Disconnect. The clock updates once per minute without a network request. Hovering or focusing a day move tile shows its destination date; an hour move tile shows the destination date, time, and time zone. These tooltips recalculate when the pointer enters the tile or it gains focus.

Events at least 48 hours old get a colored dot before the title. All-day events, timed events lasting at least one hour, and events with another invitee get a colored background. The page icon in the header filters the visible list to those highlighted events; click it again to show all. **Skins** in settings offers Green, Blue, Purple, and Rose presets, saved locally in this Chrome profile.

List repaints wait until an event-button press has delivered its click, so a preceding network response cannot detach the next 1D button mid-click. Rapid actions remain queued in order.

Move and dismiss tiles immediately hide the event. The header **Undo** arrow restores only the latest pending action before the change is sent to Google. Clicking another action hides that event and queues the previous save in the background. Leaving/minimizing the manager window queues the newest pending action. Earlier background saves do not delay or replace the newest Undo. Successful actions remove dismissed events and moves outside the selected range; moves within the range return to their chronological position without scrolling. A failed Calendar move restores the normal controls. A forced browser quit may cancel an uncommitted action. Dismissals use immutable per-dismissal records in Google Drive `appDataFolder`, plus local Chrome storage; both clients still read the previous shared JSON file. This avoids clients overwriting each other's dismissals. Records are pruned when their event start is more than 365 days old; future-event dismissals are retained.

Move destinations are calculated when the tile is clicked; header Undo restores the event without changing Calendar. Full Calendar search results display newest dates first; the regular review list remains oldest first.

**Events recently moved** in the settings menu lists the latest ten confirmed moves, including destination and move time. The small move records are saved locally and shared with Android through Drive. Older moves from before this feature cannot be reconstructed. Successful sync keeps ten records and prunes entries older than 30 days; a Drive error leaves the confirmed Calendar move intact and retries its local history record later.

If Chrome cannot save the small sync-status record, Sync details reports the browser-storage error. That diagnostic write does not interrupt a successful Calendar refresh or Drive action; the next status update retries it.

Click the magnifying-glass button beside the title to filter the loaded list. To refresh, click the header refresh icon, drag the event list down about 100 pixels from its top with a mouse/pointer, or scroll upward past the top with a wheel/trackpad. Release after “Release to refresh” appears. **Search Calendar** looks across past and future events in the primary calendar and shows read-only results. The top-right menu has a Refresh fallback, Disconnect, one Window row that opens presets and custom lookback (1–365 days)/lookahead (0–36500 days), dark mode, and Skins. Dark mode is the default. Disconnect clears the extension's cached Google authorization and stops automatic reconnect until **Connect Google Calendar** is clicked; switching to a different account requires another Chrome profile because `chrome.identity.getAuthToken` normally uses the profile's primary Google account.

## One-time Google setup

1. The Chrome Extension OAuth client has been created in Google Cloud Console project **411250810503**, with Item ID `halmnakmjhbkchjgmbonmhadenodlhhd`. Its public client ID is already configured in [`manifest.json`](manifest.json). The extension's public manifest key fixes this ID for unpacked installs.
2. Confirm the **Google Calendar API** and **Google Drive API** are enabled in the same project. If the OAuth app is in Testing mode, add the Google account you will use under **Google Auth platform → Audience → Test users**.

## Install in Chrome

1. In the Chrome profile for the same Google account as Android, open `chrome://extensions`.
2. Turn on **Developer mode**, then click **Load unpacked** and choose this repo's `chrome-extension` folder.
3. The extension ID shown in Chrome should be `halmnakmjhbkchjgmbonmhadenodlhhd`. If it differs, stop and check the folder and manifest key before signing in.
4. Click the Notification Manager toolbar button once to open its window, then click **Connect Google Calendar** and approve the requested Calendar and Drive access. The account shown in the settings menu should match the Android app's account.
5. Quit Chrome completely with **Chrome → Quit Google Chrome**, then reopen it. The manager should open in its own window. Closing all regular browser windows and opening Chrome again should also open or focus the manager.

After an extension code change, click **Reload** on `chrome://extensions`. The manager window reloads its updated page automatically; if Chrome has discarded the old tab, the extension replaces its dedicated window. A move or dismissal still in its configurable Undo period may be canceled by an extension reload. The event list refreshes on each manager-window open, when the window regains focus, on a pull-down gesture, or from the menu; it does not use push or background polling.

The Google Cloud OAuth client and interactive Google sign-in are required before Calendar data can be displayed. This repo never contains an access token or client secret. Calendar move and dismissal actions make live changes after you click their tiles and let the Undo period expire, take another action, or leave the window. Test with newly created events, never with existing personal events.

## Local checks

From this folder, run `npm test`. Tests use fixture events and do not access Google Calendar or Drive.

Undo defaults to 5 seconds. The three-dot menu’s **Undo Time** setting accepts a whole number from 1 to 30 seconds and is saved locally. Only the newest action can be restored by the header Undo arrow. Pending and saving events stay hidden. Failed actions return to the queue with an error; successful moves within the range return to their chronological position without scrolling. Changing Undo Time applies to subsequent actions.
