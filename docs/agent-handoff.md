# Notification Manager: review handoff

This repository contains an Android app and a Chrome extension for one signed-in user's **primary** Google Calendar. Both show a configurable recent window (seven past days and the rest of today by default), calculate rounded age, and let the user move or dismiss events. ## Safety and review boundary

**Do not move, dismiss, recolor, delete, or create real events in the user's Calendar.** The user has explicitly forbidden changes to existing events for testing. Use unit tests and fixtures. If a live integration check is indispensable, ask first and use a newly created event clearly named `Test Event - 1`, `Test Event - 2`, etc. Do not read or disclose OAuth tokens, local account data, or dismissal contents in review output. A code review is requested; suggest changes with file/line references, and distinguish confirmed defects from hypotheses.

## Behavior to validate

1. **Calendar boundaries and order:** Compare Android and extension results around midnight, daylight saving transitions, all-day events, and mixed dates. The display range uses the device's local date for the lookahead. The list is oldest date first and all-day first for that date. Google all-day events have an exclusive end date. Check search ordering and post-move reinsertion too.
2. **Move integrity:** Tiles target current device time plus 1/2/3/4/7 days or 1/4/8 hours, or the chosen date at current local clock time. All-day events stay all-day with the same span and get a 0D tile instead of hourly tiles. Recurring instances expose only Edit and Dismiss and have a server-side move guard. Verify instances, exceptions, event time zones, duration, and mutation failure handling. Do not use real events to investigate.
3. **Undo and lifecycle:** A tile stages a 30-second Undo state. Another action or leaving/minimizing commits it; Undo cancels. Check concurrent clicks, timer races, app/browser shutdown, a picker that loses window focus, stale events after refresh, and whether failures restore actionable UI with a clear error.
4. **Dismissal sync:** Both clients read the legacy JSON file in Google Drive `appDataFolder` and publish new dismissals as independent, immutable v2 metadata records. They merge local, legacy, and v2 records as a union, and prune v2 records whose event start is more than 365 days old. Future-event dismissals must survive the merge; an earlier bug discarded them immediately, making a future event reappear without an error. Pending local markers are retried when connection returns and cleared when Drive confirms them; synced keys remain cached for offline display. Review pagination, duplicate markers, simultaneous writes from two clients, offline behavior, token expiry, status accuracy, and 30-day history. The legacy file stays read-only.
5. **Account scope and links:** Only the account's primary calendar should be read, even if it can view other calendars. Check OAuth scopes, sign-out/switch behavior, normal vs Incognito tab targeting, URL validation, and handling of a Docs location opened under a different browser/OS account. The pencil's `eventedit/<eid>` route follows an observed Google Calendar URL pattern supplied by the user rather than a documented Calendar API link; validate its behavior and fallback across accounts, browsers, and recurring instances.
6. **UI parity/accessibility:** Compare filters, search, themes, highlighted events, 48-hour dot, count, header clock, ribbon placement, full title after expansion, three-line truncation, touch targets, keyboard focus, screen-reader labels, and contrast in dark/light modes. Both clients support pull-to-refresh and have an explicit Refresh item in the side menu. Extension pull-down supports mouse/pointer dragging and wheel/trackpad overscroll at the top. Check that dragging does not accidentally activate event links or tiles. Search Calendar returns read-only remote results.
7. **Maintainability/security:** Identify duplicated behavior that could drift, overly large UI functions, unnecessary API calls, unsafe URL handling, scopes broader than necessary, data retained beyond the lookback, missing error states, and tests that exercise meaningful boundaries. Propose small, concrete refactors with tradeoffs; do not change user-facing semantics without calling that out.

## Known limits / intended future work

- No Google Calendar push delivery yet. Each client reloads on opening/focus or explicit refresh; see the push plan.
- Google Calendar does not provide Checker Plus's private dismissal state. Move operations sync through Calendar itself; dismissal sync is between this Android app and this extension through Drive.
- Skins, review-window presets, and lookback/lookahead preferences are stored separately per client. Dismissal records sync through Drive. The real-event filter starts off each time the screen/window opens. Offline Calendar caches are local only; moves are not queued while offline. `navigator.onLine` can say online when Google is unreachable, so API errors must still set Sync needs attention.
- A recurring dismissal is keyed to the expanded instance ID and its current start. It does not affect future series instances; changing the dismissed instance's start later can make it reappear. Test that edge case before changing the cross-client key format.
- Pencil buttons try Google's `eventedit/<eid>` web route derived from `htmlLink`; the route is not documented as a Calendar API contract and falls back to the event view if no `eid` exists. Opening a Google Docs location cannot reliably force the app's connected Google account.
