# Notification Manager: review handoff

This repository contains an Android app and a Chrome extension for one signed-in user's **primary** Google Calendar. Both show a configurable recent window (seven past days and the rest of today by default), calculate rounded age, and let the user move or dismiss events. The extension opens a dedicated window on Chrome startup. Read the [root README](../README.md), [extension README](../chrome-extension/README.md), [dismissal sync notes](dismissal-sync.md), and [push sync plan](push-sync-setup.md) before reviewing code.

## Safety and review boundary

**Do not move, dismiss, recolor, delete, or create real events in the user's Calendar.** The user has explicitly forbidden changes to existing events for testing. Use unit tests and fixtures. If a live integration check is indispensable, ask first and use a newly created event clearly named `Test Event - 1`, `Test Event - 2`, etc. Do not read or disclose OAuth tokens, local account data, or dismissal contents in review output. A code review is requested; suggest changes with file/line references, and distinguish confirmed defects from hypotheses.

## Code map

- Android UI and action lifecycle: [`app/src/main/java/com/noanadeem/notificationmanager/MainActivity.kt`](../app/src/main/java/com/noanadeem/notificationmanager/MainActivity.kt). Jetpack Compose renders the connected screen, search, menu, real-event filter, ribbons, picker, 30-second Undo state, refresh gesture, and error messages. Opening an event uses its Google Calendar `htmlLink` with Android `ACTION_VIEW`.
- Android Calendar model, API fetch/search, parsing, ordering, and move calculations: [`CalendarEvents.kt`](../app/src/main/java/com/noanadeem/notificationmanager/CalendarEvents.kt). `sortCalendarEvents` uses the phone's date descending and places all-day events before timed events **within the same date**. A highlighted/“real” event is all-day, at least 60 minutes long, or has an attendee other than the owner.
- Android Drive and local dismissal merge: [`Dismissals.kt`](../app/src/main/java/com/noanadeem/notificationmanager/Dismissals.kt). Other helpers: [`ClockLabels.kt`](../app/src/main/java/com/noanadeem/notificationmanager/ClockLabels.kt), [`Skins.kt`](../app/src/main/java/com/noanadeem/notificationmanager/Skins.kt).
- Extension manifest and OAuth scopes: [`chrome-extension/manifest.json`](../chrome-extension/manifest.json). Startup/focus behavior: [`background.js`](../chrome-extension/background.js).
- Extension UI/actions: [`window.js`](../chrome-extension/window.js), [`window.html`](../chrome-extension/window.html), [`window.css`](../chrome-extension/window.css). The native date picker opens from the Calendar tile and selecting a date stages an Undoable move immediately. Title/open clicks are rate limited per URL for eight seconds; the `htmlLink` opens in a regular Chrome window. The page icon filters highlighted events.
- Extension Calendar/Drive requests: [`google.js`](../chrome-extension/google.js). Pure date, sort, move, dismissal, and highlight helpers: [`model.js`](../chrome-extension/model.js). Undo sequencing: [`undo.js`](../chrome-extension/undo.js). Tab opening and repeat-click guard: [`open.js`](../chrome-extension/open.js). Flyout positioning: [`layout.js`](../chrome-extension/layout.js).
- Tests: Android [`app/src/test/java/com/noanadeem/notificationmanager/`](../app/src/test/java/com/noanadeem/notificationmanager/); extension `chrome-extension/*.test.js`. Run `./gradlew testDebugUnitTest assembleDebug` at the repo root and `npm test` in `chrome-extension/`. These use fixture events and should not make live Google calls.

## Behavior to validate

1. **Calendar boundaries and order:** Compare Android and extension results around midnight, daylight saving transitions, all-day events, and mixed dates. The display range uses the device's local date for the lookahead. The list is newest date first and all-day first for that date. Google all-day events have an exclusive end date. Check search ordering and post-move reinsertion too.
2. **Move integrity:** Tiles target current device time plus 1/2/3/4/7 days or 1/4/8 hours, or the chosen date at current local clock time. All-day events stay all-day with the same span and get a 0D tile instead of hourly tiles. Verify recurring instances, exceptions, event time zones, duration, and mutation failure handling. Do not use real events to investigate.
3. **Undo and lifecycle:** A tile stages a 30-second Undo state. Another action or leaving/minimizing commits it; Undo cancels. Check concurrent clicks, timer races, app/browser shutdown, a picker that loses window focus, stale events after refresh, and whether failures restore actionable UI with a clear error.
4. **Dismissal sync:** Both clients use the same JSON file in Google Drive `appDataFolder`, merge it with local records as a union, and prune records beyond the 365-day maximum lookback during sync. Inspect duplicate files, simultaneous writes from two clients, offline behavior, token expiry, conflicts, and whether a locally saved but Drive-failed dismissal is clearly reported.
5. **Account scope and links:** Only the account's primary calendar should be read, even if it can view other calendars. Check OAuth scopes, sign-out/switch behavior, normal vs Incognito tab targeting, URL validation, and handling of a Docs location opened under a different browser/OS account. The Google Calendar API `htmlLink` is a view link; direct edit mode is not currently supported.
6. **UI parity/accessibility:** Compare filters, search, themes, highlighted events, 48-hour dot, count, header clock, ribbon placement, full title after expansion, three-line truncation, touch targets, keyboard focus, screen-reader labels, and contrast in dark/light modes. The app uses pull-to-refresh; the extension has a refresh icon. Search Calendar returns read-only remote results.
7. **Maintainability/security:** Identify duplicated behavior that could drift, overly large UI functions, unnecessary API calls, unsafe URL handling, scopes broader than necessary, data retained beyond the lookback, missing error states, and tests that exercise meaningful boundaries. Propose small, concrete refactors with tradeoffs; do not change user-facing semantics without calling that out.

## Known limits / intended future work

- No Google Calendar push delivery yet. Each client reloads on opening/focus or explicit refresh; see the push plan.
- Google Calendar does not provide Checker Plus's private dismissal state. Move operations sync through Calendar itself; dismissal sync is between this Android app and this extension through Drive.
- Skins and lookback/lookahead preferences are stored separately per client. Dismissal records sync through Drive. The real-event filter starts off each time the screen/window opens.
- Opening a Google event uses its documented `htmlLink`; it cannot reliably force the event editor. Opening a Google Docs location cannot reliably force the app's connected Google account.
